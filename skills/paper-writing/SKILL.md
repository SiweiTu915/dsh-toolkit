# 论文/报告写作协议(AIOps / 时序 / LLM / 微服务 RCA)

写作顺序固定:**先图表,再实验,再方法,再 related work,最后 intro 和 abstract**。不要从 intro 开始写。

## 1. 写作顺序与结构

1. 图表(数据先行):把所有表格/图按论文顺序排好——正文结构跟着图表演进
2. 实验章节:数据集 → 指标 → 基线 → 主结果 → 消融 → case study
3. 方法章节:问题形式化 → 方法骨架 → 关键设计决策 → 复杂度/成本
4. Related work:3 类邻域(时序异常检测 / 根因分析 RCA / LLM for Ops),定位差异
5. Intro:动机 → 现有方法不足 → 我们的方法 → 贡献列表
6. Abstract:最后写,一句话压缩全文

## 2. 各章节要点

**Intro(评审第一印象)**
- 动机用真实数据说话(工业故障成本、告警风暴规模),不要空泛
- 贡献列表 3-4 条,每条可验证(对应一个实验或一个设计决策)
- 明确"我们不是第一个用 LLM 做 X 的,我们的差异是 Y"

**Related work**
- 每条 related 都要回答:它是什么、和我们的差异、为什么不替代我们
- 按方法范式分组,不是按时间流水账

**方法**
- 形式化问题定义(输入/输出/目标函数)
- 每个设计决策给一句理由(为什么不选替代方案)
- LLM 部分:prompt 设计、上下文构造、成本控制都要写(评审会问)

**实验(领域惯例)**
- 数据集表:名称/规模/故障类型/来源
- 基线公平性:同协议同指标,写明差异(如点调整 F1 用没用)
- 消融表:组件逐一移除
- case study:1-2 个真实例子(检测出的异常片段 / RCA 定位正确的调用链 / LLM 输出示例)
- 局限小节:**主动写**,评审最恨"方法宣称普适但只测了 2 个数据集"

## 3. 图表与格式规范

- 表格:三线表,均值±std,最优加粗、次优下划线
- 图:异常检测结果曲线 / RCA@k 曲线 / 成本-性能散点;每张图 caption 独立可读
- 引用:优先领域公认工作;引用要真的读过的(不要幻觉引用——用 paper-reading 的笔记核对)

## 4. 评审视角自检清单(写完逐条过)

- [ ] 贡献列表每条都有实验支撑?
- [ ] 基线都是最强的吗?有没有只打弱基线的嫌疑?
- [ ] 数据集是标准公开的吗?自建的有没有说明偏差?
- [ ] 消融完整吗?每个组件都有对照?
- [ ] 有没有过度声称(把子集结果说成普适结论)?
- [ ] LLM 实验:API 成本、seed、prompt 版本都记录了吗(可复现)?
- [ ] 局限小节存在且诚实?
- [ ] abstract 与正文一致(数字、声称)?

## 5. 输出

论文/报告正文 + 一张"评审可能的问题 & 我们的回答"清单。写作时遇到不确定的数字,标注 TODO 回去核对,不要编。
