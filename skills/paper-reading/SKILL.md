# 论文阅读协议(AIOps / 时序 / LLM / 微服务 RCA)

按三步走,每一步产出明确结果。不要跳过第一步直接精读。

## 1. 分诊(约 2 分钟)

读标题、摘要、图表标题,回答:
- **相关吗?**(与本方向:时序异常检测 / 根因分析 RCA / LLM for Ops / 可观测性)
- **新吗?**(方法核心是不是已有工作的换皮)
- **值不值得精读?** 三选一:`精读` / `速读存档` / `归档不读`

输出一句话判断,例如:"这篇是 LLM 做微服务 RCA 的实证工作,方法上有新意(用因果图约束 LLM 推理),值得精读"。

## 2. 精读(四段式)

按下面四段提取,每段 2-5 条要点:

1. **问题定义**:解决什么问题?为什么重要(工业动因/数据动因)?问题形式化了吗?
2. **方法**:输入是什么(单指标时序?多指标?metrics+logs+traces?)、方法骨架(检测/定位/解释的哪一环)、关键设计决策、与最近邻工作的差异
3. **实验**:数据集(标准还是自建?)、基线(是否公平——同数据同协议?)、指标、消融、case study
4. **局限**:作者承认的 + 你没看到的(数据泄露、评估偏差、泛化性)

## 3. 批判性评估(重点)

- **基线公平性**:是否只对比了弱基线?是否用了同样的训练/评估协议?
- **数据集**:标准数据集(SMD/MSL/PSM/SWaT/WADI、TrainTicket 等)还是自建?规模够吗?
- **消融完整性**:每个组件都有对应实验吗?
- **可复现性**:代码开源了吗?随机种子、超参细节够吗?
- **对我们的启示**:与本工作/你的 idea 的关系——是 gap、是 baseline、还是可复用的组件?

## 4. 输出统一笔记格式

```markdown
## 论文标题(作者, 会议/年份)
- 一句话贡献:
- 方法骨架:
- 实验结论:
- 局限:
- 对我们的启示:
```

同一主题的多篇笔记放同一个文件(按主题归档),方便后续写 related work 直接引用。
