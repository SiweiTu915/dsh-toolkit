# 实验结果整理与分析协议

目标:把原始实验输出变成**可直接进论文的表格/图表 + 每个结论都有数据支撑**的分析。

## 1. 数据整理

- 汇总所有运行(各 seed)到一张表:每行一个配置(方法/数据集/seed),每列一个指标
- 计算均值 ± 标准差;检查异常值(记录而非删除,标注原因)
- 固定表格格式:`方法` × `数据集` 矩阵,每个格子 `均值±std`,**最优加粗、次优下划线**(论文惯例)

## 2. 统计显著性

- 多次 seed 之间:配对 t 检验或 Wilcoxon 符号秩检验(非正态时)
- 报告 p 值(或符号标记 †/**),同时报告效应量,别只看 p
- 显著但 Δ 很小(如 0.1% F1)要诚实指出:统计显著 ≠ 实际有意义

## 3. 消融解读

- 按贡献排序组件:"去掉 X 掉 Δ₁,去掉 Y 掉 Δ₂"
- 为每个显著消融给出**机制解释**(为什么这个组件重要),解释不了就标为待验证,不要硬编故事
- 交互项:两个组件同时去掉 ≠ 各自去掉之和 → 说明有协同/冗余

## 4. 错误分析(常被漏掉但最值钱)

- 收集失败 case,按类别分组(如:检测类漏报多发生在慢漂移;RCA 类定位错误集中在传播链末端;LLM 类幻觉集中在证据不足场景)
- 每个类别给出 1-2 个具体例子 + 原因假设 + 可能的改进方向
- 错误分析往往就是论文的"Discussion"和后续工作的起点

## 5. 可视化规范(领域惯例)

- 时序异常检测:检测结果曲线(真实 vs 预测,标注异常区间)、PR 曲线/F1 随阈值变化
- RCA:RCA@k 的 Top-k 命中曲线、定位正确的调用链示例(截图/示意图)
- LLM 方法:真实输出示例(含正确/错误引用)、成本-性能散点
- 统一字体/配色/坐标轴;每张图必须有能独立读懂的 caption

## 6. 结论写作

每条结论格式:`方法在 数据集 上,相比 基线,在 指标 上 提升/持平/下降 Δ(±std)`,且:
- 只写数据支持的结论;泛化性结论(如"在真实生产环境更有效")必须标注为推测
- 每条结论对应论文正文的一处位置(表格编号)
- 末尾列"本分析未覆盖的局限"(数据偏差/指标局限/算力限制)

## 7. 输出

一份《实验结果分析报告》:汇总表 / 显著性表 / 消融表 / 错误分析 / 图 / 结论清单(每条带数据引用)+ 局限。这份报告直接是论文实验章节的草稿。
