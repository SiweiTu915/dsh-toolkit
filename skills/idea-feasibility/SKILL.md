# Idea 可行性评估(AIOps / 时序 / LLM / 微服务 RCA)

目标:把一个模糊想法变成**可验证的假设 + 明确的 Go/No-Go 决策**。全程四步,按顺序走。

## 1. 问题定义

把 idea 写成**一句话可验证假设**:

> 用 X(方法)在 Y(任务/场景)上,相比 Z(最强基线),能在 W(指标)上提升 Δ。

反例:"用 LLM 做 RCA"→ 不可验证;正例:"用因果图约束的 LLM 推理,在 TrainTicket 故障注入上,RCA@3 相比无约束 LLM 提升 ≥5 个百分点"。

## 2. 数据检查(领域特有)

- **时序异常检测**:数据集清单 SMD / MSL / PSM / SWaT / WADI——数据可得吗?下载源?标注是点级还是区间级?评估协议(点调整 F1 与否)和你的一致吗?
- **微服务 RCA**:TrainTicket / SockShop / Online Boutique + 故障注入工具——你有环境吗?故障类型覆盖(CPU/内存/网络/异常)够吗?trace 数据有 span 关联吗?
- **LLM 相关**:评测需要人工标注吗?成本多少?GPT/DeepSeek API 调用量估算?

产出:**数据可得性结论**(✓ 现成 / 需改造 / 需自建 + 工作量估算)。

## 3. 基线检查

- 列出**最该打的 3-5 个基线**(领域最强 + 最近相关工作 + 1 个简单启发式兜底)
- 每个基线:代码是否开源?能跑通吗?作者是否报告了同类指标?
- 明确我们相对每个基线的**增益假设**——说不出的增益假设,就是没有 idea

## 4. 成本与风险

- 预实验规模(数据集子集 / 简化设置)预计几天?
- 正式实验预计几周?算力/API 预算?
- 最大失败模式是什么?有没有 Plan B(换数据/换基线/降级为实证分析)?

## 5. 输出

```markdown
## 可行性结论:Go / No-Go / 需预实验
- 一句话假设:
- 数据: 
- 基线: 
- 成本: 
- 风险与 Plan B: 
- 最小预实验设计(若 Go):数据集子集 + 1 个主基线 + 1 个消融,3 天内可跑完
```

规则:**No-Go 不是失败,是省了 3 周**。结论偏向 No-Go 时,指出最可能让它翻转的条件。
