# 实验设计协议(AIOps / 时序 / LLM / 微服务 RCA)

先定指标和数据集,再定基线与消融,最后写预实验计划。**指标不先定,实验不许跑。**

## 1. 数据集(领域标准清单)

**时序异常检测**:SMD、MSL、PSM、SWaT、WADI(下载源公开;注意标注粒度:点级 vs 区间级,评估协议是否用点调整)
**微服务 RCA**:TrainTicket、SockShop、Online Boutique + 故障注入(CPU 高负载/内存泄漏/网络延迟丢包/服务异常);有 trace 时确认 span 关联与调用链完整性
**可观测性数据形态**:单指标时序 / 多维指标矩阵 / logs(结构化还是自由文本)/ traces(分布式链路)——你的方法吃哪种形态,数据是否匹配

选择规则:优先**标准公开数据集**(评审认可、可复现);自建数据必须说明生成方式和偏差。

## 2. 指标(领域标准)

- **时序异常检测**:F1、PR-AUC(区间级评估常用点调整 F1——是否用、为何用,写清楚);F1@k(前 k 个告警)
- **RCA/故障定位**:RCA@k(正确答案在前 k 命中)、hit-rate、MTTR(平均修复时间)、定位精度;多故障场景要分开报
- **LLM 参与的方法**额外报:引用率(证据是否真实)、幻觉率/错误引用、API 成本与延迟

规则:主指标 1-2 个(论文标题里那个),其余作为辅助指标;所有基线用**同一套**指标与协议。

## 3. 基线

分层打,至少覆盖:
1. **领域最强基线**(近年 SOTA,同数据集同协议)
2. **最近相关工作**(最接近你的方法)
3. **简单启发式兜底**(如阈值法/拓扑传播/无 LLM 版本)——证明增益不是来自复杂度

每个基线:代码可用性、训练/推理成本、与你方法的公平对齐(输入相同、算力相近)。

## 4. 消融矩阵

把方法拆成组件,逐一移除:
- 检测类:输入模态(单指标/多指标/融合)、模型主干、后处理(点调整/告警抑制)
- RCA 类:拓扑信息、因果推断、LLM 推理约束、证据检索
- 矩阵要能回答:"哪个组件贡献最大?去掉它掉多少?"——结论进论文

## 5. 协议:预实验 → 正式实验

**预实验(3 天内)**:
- 数据集子集(如 2-3 个数据集 × 少量故障类型)
- 1 个主基线 + 1 个关键消融
- 目标:验证 pipeline 通、增益方向正确、指标有意义
- 预实验失败不丢人——回到 idea-feasibility 调整假设

**正式实验**:
- 固定随机种子,多次运行(≥3 或 ≥5)取均值 ± 标准差
- 显著性检验(配对 t 或 Wilcoxon)在多次运行上做
- 记录每个实验的配置(超参/种子/数据集版本),保证可复现
- 实验日志按"一个实验一个文件"归档,结论与数字绑定

## 6. 输出

实验方案文档:假设 / 数据集表 / 指标定义 / 基线清单 / 消融矩阵 / 预实验计划 / 时间线。写完先自查:**如果我是评审,这个设计会被问什么问题?**
