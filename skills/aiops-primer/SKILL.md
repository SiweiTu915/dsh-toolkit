# AIOps / 时序 / RCA 领域速查

给模型用的领域知识底座。涉及本领域任务时先过一遍,确保术语和评估惯例对齐。

## 1. 核心术语

- **可观测性三支柱**:Metrics(指标,数值型时序)、Logs(日志,自由文本/半结构化)、Traces(分布式调用链,span 含父子关系与耗时)
- **SLO/SLI/SLA**:服务目标/实际指标/协议——告警与故障判定的依据
- **异常检测 vs 根因分析**:检测(发现问题:哪个指标/哪个服务异常)vs RCA(定位问题:为什么,哪个根因服务/代码/配置);两者常串联成 pipeline
- **告警风暴/告警关联**:大量相关告警需压缩关联到同一根因
- **漂移**:概念漂移/数据漂移——生产模型失效的常见原因

## 2. 方法分类(写 related work / 选基线时用)

**时序异常检测**:
- 统计:阈值、ARIMA、指数平滑(简单兜底基线)
- 浅层学习:Isolation Forest、One-Class SVM、PCA 类
- 深度:DeepSVDD、LSTM/TCN 重构误差、Transformer 变体、自监督对比学习

**微服务 RCA**:
- 拓扑/依赖基:沿调用链传播推断
- 因果基:PC/干预、Granger、随机扰动注入
- 统计关联:PCF/PCA、故障传播图
- 机器学习基:监督定位、表征聚类
- LLM 基(近年热点):LLM + 证据检索/图约束/多模态融合

**LLM for Ops 特有议题**:证据检索(日志/指标/拓扑→上下文)、幻觉控制、成本-延迟、在线 vs 离线评估

## 3. 标准数据集(写实验章节时核对)

- **单变量/多变量时序异常**:SMD(服务器指标)、MSL/PSM(航天/卫星遥测)、SWaT/WADI(水处理工控)——公开、标注区间
- **微服务故障**:TrainTicket(铁路订票系统)、SockShop、Online Boutique——配合故障注入(CPU/内存/网络/异常)产生 RCA 数据
- 注意:同一数据集在不同论文里的**评估协议可能不同**(点调整与否、训练/测试切分),引用时写明你用的是哪个协议

## 4. 指标速查

- 异常检测:F1、PR-AUC、F1@k;点调整 F1(segment-aware)是常见惯例,但**用不用要在论文里声明**
- RCA:RCA@k(前 k 命中)、hit-rate、MTTR;多故障场景分开报
- 定位质量:错误跳数、定位层级(服务级 vs 实例级 vs 代码级)

## 5. 常见评估陷阱(评审/自查必查)

1. **数据泄露**:用整段序列训练再在中间段测试;或测试集参与过特征工程
2. **基线不公平**:只打弱基线;不同方法用不同协议(如自己用点调整、基线用逐点)
3. **检测-定位耦合**:RCA 的输入里混入了答案(如把故障注入日志直接喂给 LLM)
4. **LLM 幻觉未被校验**:LLM 引用的日志/指标不存在——必须做引用真实性校验
5. **单数据集声称普适**:至少 2-3 个数据集 + 消融 + 局限声明
6. **微服务 trace 与单机时序的区别**:多服务间存在调用依赖,单指标独立建模会忽略传播关系

## 6. 使用方式

- 任务开始前:通读第 1-2 节对齐术语与任务定位(检测?RCA?全链路?)
- 设计实验/写 related work:查第 2-3 节
- 写实验章节/自查:查第 4-5 节
